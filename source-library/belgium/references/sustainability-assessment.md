# Belgium source-rule sustainability assessment

Assessment date: 18 October 2026  
Scope: all 39 records in candidate-manifest.json (39 candidates; 0 accepted). Two records have prior converted review artifacts, but neither is backed by an implemented repeatable retrieval/conversion rule. This is a proposed-route review only; no candidate receives a rule sustainability verdict or confidence rating.

## Summary

The strongest prospective legislation route is Justel, reached through stable ELI-style records and the IBZ legislation index. The observed Immigration Law page is a long consolidated HTML record with 136 archived versions and 331 implementing decrees. The public mirror also contained an earlier five-candidate Belgium inventory, with two converted review artifacts for IBZ family guidance and Federal Justice adoption guidance. Those artifacts are preserved and counted, but they are not active retrieval rules. No Belgian byte capture, identity validator, deterministic converter, offline replay, or change detector exists.

The Immigration Office is the best current discovery route for annexes and EU residence guidance, but JavaScript-dependent pages, incomplete rendered guidance, a human-verification challenge, and the failed Annex 19ter PDF endpoint make automated access and payload identity uncertain. Versioned direct files must be rediscovered from official parent indexes. Foreign Affairs provides a central visa hub and a current competence matrix, but mission procedures and outsourced providers vary by applicant location. No API registration or bulk-use route was verified.

Remedy and access-to-records coverage is institutionally fragmented. Federal, Walloon, Flemish, and Brussels records have different scopes; the German-speaking Community search is incomplete. The federal Ombudsman and selected court material cannot replace statutory appeal routes, and the RvV/CCE site returned HTTP 403. Existing official route evidence therefore supports a cautious manual discovery workflow, not a sustainable automated Belgian source pack.

## Cross-cutting sustainability risks and open routes

- No Belgian API, registration route, or permitted bulk retrieval path was established. This is a documented unknown, not evidence that no API exists.
- The two preserved converted review candidates contain retrieval timestamps and raw-response hashes, but the raw HTML captures are not present. Their converted text cannot be independently replayed from source bytes, and one old README also contained an unrelated France-Visas statement that has been removed during reconciliation.
- Direct-page and browser-research access does not prove plugin-runtime access. IBZ JavaScript pages, the human-verification challenge, Annex 19ter's HTML error response, and the RvV/CCE 403 response require runtime-specific checks before an adapter can be considered feasible.
- Versioned PDFs and dynamic indexes must be linked by a stable parent record. A pinned filename or successful HTTP response alone does not establish current form identity.
- The candidate set remains incomplete for German-speaking Community access-to-records material, municipal and community-level records, broader mission practice, full court coverage, the 2018 personal-data processing law, and national civil-status/adoption sources.
- Search query strings were not retained as a complete transcript. Before implementing search-based discovery, record the exact native-language queries, dates, official portals, and result scope so that no-result claims can be reproduced.
- No candidate has an implemented retrieval rule, response validator, deterministic converter, saved source bytes, offline replay, or repeatable change detector. Prior accepted text and review state therefore do not yet exist for Belgium.

## Completion gate for any future Belgian rule

Do not promote a candidate based only on its URL or a live fetch. A rule would need official-source identity and jurisdiction checks, bounded redirects, status/media-type/file-signature/size/language validation, exact-byte provenance and hashing, deterministic content extraction, offline replay against a captured response, and a review-only failure/change state. Forms and changing consular instructions should be resolved through their official parent indexes. Reviewers must separately assess legal scope, currentness, completeness, and regional or language coverage.
